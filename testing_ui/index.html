Plaintext means information is sent in readable, unencrypted form. Anyone inspecting network routers, Wi-Fi traffic, or intermediate servers can read the message word for word.

QuMail's 3 Security Levels Overview

QuMail implements three distinct security configurations to demonstrate plaintext transmission, post-quantum key encapsulation + symmetric encryption, and one-time pads.

Level 1

Plaintext Transmission

  • What it does: Transmits raw readable message without payload encryption.
  • What travels: Cleartext JSON payload + Dilithium digital signature.
  • Attacker sees: Full readable email body.
  • Bob receives: Direct readable message.
  • Purpose: Baseline demonstration of insecure transmission.
Level 2

Kyber-1024 KEM + AES-256-GCM

  • What it does: Establishes post-quantum shared secret via Kyber KEM and encrypts body via AES-GCM.
  • What travels: Kyber ciphertext + AES ciphertext + Nonce + Signature.
  • Attacker sees: Scrambled hex ciphertexts (no plaintext exposed).
  • Bob receives: Decapsulates shared secret to decrypt email.
  • Purpose: Complete Post-Quantum Secure Email Flow.
Level 3

Quantum One-Time Pad (OTP)

  • What it does: Encrypts payload byte-by-byte using bitwise XOR with single-use key.
  • What travels: OTP ciphertext (+ debug key in demo mode).
  • Attacker sees: Random byte sequence.
  • Bob receives: Re-applies XOR key to recover original bytes.
  • Purpose: Mathematical perfect secrecy simulation.

Why Level 2 Exists — Plaintext to Ciphertext

We don't want secret email text traveling through public network routers. Before entering the network, readable plaintext must be transformed into unreadable ciphertext.

Ciphertext

Ciphertext is the scrambled, unreadable encrypted form of data. Without the correct decryption key, ciphertext appears as random, unintelligible bytes.

AES-256-GCM — The Symmetric Lock

AES (Advanced Encryption Standard with 256-bit keys in GCM mode) is the algorithm that encrypts the actual email content. AES is a symmetric cipher, meaning Alice and Bob must use the exact same secret key.

The Fundamental Symmetric Problem

If Alice and Bob need the SAME secret AES key to encrypt and decrypt, how can Alice share this key with Bob over an insecure Internet without an attacker stealing it?

👉 THIS IS WHERE KYBER KEM COMES IN!

Kyber — Establishing a Shared Secret Without Sending the Secret

Kyber (ML-KEM) is a Post-Quantum Key Encapsulation Mechanism. It solves the key distribution problem: Alice and Bob derive matching shared secret keys without ever sending the secret across the network!

STEP 1

Bob Generates Key Pair

Bob creates a Public Key 🔓 (can be shared publicly) and a Private Key 🔑 (kept secret in Bob's vault).

🔒 Bob's Private Vault: kyber_sk_8f... (Stays with Bob)
STEP 2

Bob Shares Public Key Only

Bob sends ONLY his Public Key 🔓 across the Internet to Alice. Attacker can see the Public Key, which is safe because it is designed to be public.

STEP 3

Alice Encapsulates

Alice takes Bob's Public Key 🔓 and runs Kyber Encapsulation. This generates two outputs:

  • Shared Secret (ABC123): Kept by Alice locally.
  • Kyber Ciphertext (K9X2F7...): Encapsulated key payload.
STEP 4

Alice Transmits Kyber Ciphertext

Alice DOES NOT send the Shared Secret (ABC123). Alice sends ONLY the Kyber Ciphertext across the network to Bob.

Attacker sees: Kyber Ciphertext (K9X2F7...) | Attacker CANNOT see: Shared Secret (ABC123)
STEP 5

Bob Decapsulates

Bob receives the Kyber Ciphertext and combines it with his secret Private Key 🔑 to perform Kyber Decapsulation, recovering the exact same Shared Secret (ABC123).

STEP 6

Both Hold Matching Secret

Alice: 🔑 ABC123
=
Bob: 🔑 ABC123
🚨 THE SHARED SECRET ITSELF NEVER TRAVELED THROUGH THE NETWORK FROM ALICE TO BOB.

Nonce — A Number Used Once

A nonce (Number used ONCE) is a unique 12-byte random initialization vector passed to AES-GCM for every encryption operation.

✅ VALID (Unique Nonce Per Key)

Message 1: Key A + Nonce N001

Message 2: Key A + Nonce N002

Secure GCM Operation
❌ DANGEROUS (Reused Nonce)

Message 1: Key A + Nonce N001

Message 2: Key A + Nonce N001

Vulnerable to GCM Key Recovery
Is a Nonce Secret?

No. A nonce does not need to be secret and is transmitted openly in the envelope. Its critical security requirement is uniqueness — it must never be reused with the same AES key.

Authentication Tag — Has the Ciphertext Been Tampered With?

AES-GCM is an Authenticated Encryption scheme. It generates an authentication tag (appended to the ciphertext) to ensure data integrity.

Original Ciphertext Sent: 8f92ab71c4e9...
Attacker Flips 1 Bit on Wire: 8f92ab71c4e8...
Bob's AES-GCM Check: ❌ Tag Verification Failed

Dilithium — Proving Who Signed the Message

SIMULATED IN THIS DEMO (HMAC-SHA256)

Dilithium (ML-DSA) is a Post-Quantum Digital Signature scheme used for authentication and non-repudiation.

🔒 ENCRYPTION (AES / Kyber)

Goal: Confidentiality ("Can someone read this?")

Hides the message content from eavesdroppers.

✍ DIGITAL SIGNATURE (Dilithium)

Goal: Authenticity & Integrity ("Who sent this?")

Proves Alice signed the payload and it wasn't modified.

Level 3 — Quantum One-Time Pad (OTP)

Level 3 simulates a One-Time Pad (OTP) where message bytes are combined with a single-use random key using bitwise XOR (⊕).

Bitwise XOR Demonstration
Plaintext byte (ASCII 'H'): 01001000
XOR (⊕) OTP Key byte: 10110101
= Ciphertext byte: 11111101
⚠️ Educational Debug Visibility Warning

In this demo UI, otp_key_hex is intentionally displayed in raw payloads for educational & inspection purposes. In a production secure OTP system, the OTP key must NEVER be transmitted over the network alongside the ciphertext.

What Is Real and What Is Simulated in QuMail?

✅ REAL IMPLEMENTATIONS

  • AES-256-GCM Payload Encryption: Uses Python cryptography.hazmat library.
  • Fernet Key Storage: PBKDF2 HMAC-SHA256 password derivation for key storage encryption.
  • Django REST Framework & JWT Auth: Full authentication backend.
  • Database Persistence: SQLite database models.

⚠️ SIMULATED DEMO COMPONENTS

  • Kyber-1024 KEM: Uses token-based SHA-256 simulation (crypto_core/kyber.py).
  • Dilithium Signatures: Uses HMAC-SHA256 token simulation (crypto_core/dilithium.py).
  • Quantum Channel: Simulated network link.

Under The Hood — Standardized ML-KEM & ML-DSA

NIST standardizes Kyber as ML-KEM (Module-Lattice Key Encapsulation Mechanism) and Dilithium as ML-DSA (Module-Lattice Digital Signature Algorithm). 

// KEM Key Generation
(pk, sk) = KeyGen()

// Encapsulation (Alice)
(ct, ss_Alice) = Encaps(pk_Bob)

// Decapsulation (Bob)
ss_Bob = Decaps(sk_Bob, ct)

// Result
Assert(ss_Alice == ss_Bob)
